# 算法说明

## 1. 处理流程

1. 解析 CSS 颜色并转换到 OKLCH；
2. 忽略 alpha，并将超出 sRGB 的种子映射回 sRGB；
3. 评估种子亮度、彩度和色相；
4. 按策略生成每一阶的目标 `L/C/H`；
5. 对超色域颜色固定 `L/H`、二分降低 `C`；
6. 输出 HEX、RGB 或 OKLCH 字符串；
7. 检查相邻重复、低感知差异和对比度；
8. 在色阶之上建立浅色与深色语义主题。

## 2. 默认品牌曲线

10 阶亮度初始预设：

```text
0.97, 0.93, 0.87, 0.79, 0.70, 0.61, 0.52, 0.43, 0.34, 0.25
```

彩度倍率：

```text
0.12, 0.30, 0.52, 0.74, 0.92, 1.00, 0.96, 0.86, 0.70, 0.50
```

浅端降低彩度，主色区域达到峰值，深端再次衰减。非 10 阶调用会对预设曲线做线性重采样。

## 3. 固定锚点

输入色原样作为锚点。锚点两侧按默认曲线的相对位置，分别重映射到“浅端 → 种子”和“种子 → 深端”。彩度倍率会相对锚点归一化，因此锚点的彩度保持不变。

极浅种子固定在中间阶时，浅色端空间可能非常有限；极深种子同理。算法不会静默移动调用方明确指定的锚点，而会返回质量警告。

## 4. 自适应锚点

候选阶位根据三部分评分：

```text
亮度距离 + 边缘惩罚 + 两侧空间不足惩罚
```

输入越浅，锚点越靠近浅端；越深则越靠近深端。选择完成后使用与 fixed-anchor 相同的两侧曲线重建方法。

## 5. Tonal

Tonal 只从输入提取色相和彩度特征，完整采用标准亮度曲线：

```text
C[i] = min(seedC, 0.32) × chromaFactor[i]
```

输入亮度不约束结果，因此这是面对未知用户输入时最稳健的默认策略。`recommendedIndex` 是生成色阶中与输入感知距离最近的一阶，但它不是精确锚点。

## 6. sRGB 色域映射

对超出 sRGB 的候选颜色，在 `[0, targetC]` 区间执行 28 次二分搜索：

- 固定 OKLCH `L`；
- 固定 `H`；
- 找到仍处于 sRGB 的最大 `C`；
- 最后只对浮点误差做 RGB 通道钳制。

这样比直接裁剪 RGB 通道更能保留目标亮度与色相。发生映射的阶位会记录为 `source: 'gamut-mapped'`，并加入诊断。

## 7. 中性色

中性色使用独立的 10/14 阶亮度曲线。实际彩度为：

```text
min(tintStrength, seedC × 0.18) × neutralChromaShape[i]
```

中段彩度略高，极浅与极深端更克制。默认最大彩度为 `0.025`，因此保留品牌冷暖倾向但不会变成另一套低饱和品牌色。

## 8. 深色主题

深色主题独立选择品牌和中性色阶位置：

- 页面背景使用 neutral 深端；
- 文字使用 neutral 浅端；
- 品牌默认色比浅色主题更亮；
- hover 进一步提亮，active 相对压暗；
- subtle 使用低亮度品牌色；
- `onBrand` 重新从黑/白中计算，而不是复用浅色结果。

## 9. 对比度调整

`report` 仅汇报。`adjust` 在品牌或中性色阶内寻找满足目标的候选色，再以 OKLCH 笛卡尔距离选择最接近原角色颜色的一项。若整个色阶都无法满足目标，保留原色并报告失败。边框修正会同时保证 `strong` 比 `default` 具有更高的背景对比度。

`strict` 不修改颜色；只要有检查失败，就抛出带失败清单的结构化异常。

## 10. 已知边界

- 不同色相共享同一基础曲线，黄、青、紫等困难色相主要通过色域映射修正；
- WCAG 2.x 是首版唯一强制模型，APCA 尚未加入；
- 当前输出基线是 sRGB，不提供原生 Display-P3 色板；
- 8-bit HEX 量化仍可能在极端输入下产生相邻重复，库会报告但不做随机扰动；
- 算法预设没有独立版本号；需要固定颜色输出时，应锁定 npm 包版本并保留视觉回归样本。
